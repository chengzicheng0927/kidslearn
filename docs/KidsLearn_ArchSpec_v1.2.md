## v1.2 变更说明

相对 v1.1 的三项核心调整：
1. **用户准入**：开放注册 → 邀请码机制，后台手动开户，无自助注册入口，适合小规模私密部署
2. **内容安全**：从单层过滤升级为三层防护体系，专项保护 12 岁以下儿童内容安全
3. **主动学习**：从被动响应升级为主动发起，系统可在约定时间提醒学习、推送每日任务、发起对话

## 1. 用户准入：邀请码机制

### 1.1 设计背景
系统定位为小规模私密部署，供指定家庭使用，不对外开放。彻底移除自助注册流程，改为管理员后台生成邀请码，家长凭码激活账户。

### 1.2 准入流程

```
管理员                    家长                      系统
  │                        │                          │
  │── 后台生成邀请码 ──────▶│                          │
  │                        │                          │
  │                        │── 输入邀请码 ────────────▶│
  │                        │                          │── 校验码是否有效
  │                        │                          │── 校验是否已使用
  │                        │                          │── 校验是否过期
  │                        │◀──── 展示设置表单 ────────│
  │                        │                          │
  │                        │── 提交激活 ─────────────▶│
  │                        │                          │── 创建家长账号
  │                        │                          │── 标记邀请码已使用
  │                        │◀──── 激活成功，进入 App ──│
```

### 1.3 邀请码数据模型

**invite_codes 表**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID PK | |
| code | VARCHAR(12) UNIQUE | 随机大写字母+数字，如 KL-X7R2-9MNP |
| created_by | UUID FK → admins.id | 哪位管理员创建 |
| max_uses | INT DEFAULT 1 | 通常为 1（一码一家庭） |
| used_count | INT DEFAULT 0 | |
| expires_at | TIMESTAMPTZ | 可设 7 天有效期 |
| note | TEXT | 备注，如「张三家」 |
| created_at | TIMESTAMPTZ | |
| used_at | TIMESTAMPTZ | 激活时间 |
| used_by | UUID FK → parents.id | 激活的家长账户 |

**约束**：
- CHECK (used_count <= max_uses)
- INDEX ON (code) -- 快速校验

### 1.4 邀请码生成规则
- 格式：KL-XXXX-XXXX（KL 前缀 + 4位随机 + 4位随机，大写字母+数字，去除易混淆字符 0/O/1/I）
- 有效期：默认 7 天，管理员可自定义（最长 30 天）
- 默认单次使用（max_uses=1），可配置多次
- 批量生成：管理员后台支持一次生成 1–20 个邀请码，导出 CSV
- 失效机制：过期自动失效；管理员可手动吊销未激活的邀请码

### 1.5 管理员后台
- 访问路径：/admin（Kong 网关单独路由，仅管理员 IP 白名单可访问）

**功能列表**：
- 邀请码管理：生成、查看状态（待激活/已激活/已过期）、吊销、批量导出
- 用户管理：查看所有家长账户、子账户列表、强制下线、禁用账户
- 内容安全：查看被过滤的对话记录、调整关键词黑名单、查看违规报告
- 系统监控：LLM API 用量与费用、今日活跃用户数、服务状态

### 1.6 User Service 端点

| 端点 | 方法 | 描述 | 权限 |
|------|------|------|------|
| /api/v1/auth/validate-code | POST | 校验邀请码有效性（激活前预检） | 公开 |
| /api/v1/auth/activate | POST | 凭邀请码激活，创建家长账户 | 公开（需有效码） |
| /api/v1/auth/login | POST | 登录，返回 JWT | 公开 |
| /api/v1/admin/invite-codes | GET/POST | 查询/生成邀请码 | admin |
| /api/v1/admin/invite-codes/{id}/revoke | POST | 吊销邀请码 | admin |
| /api/v1/admin/users | GET | 查看所有用户 | admin |
| /api/v1/admin/users/{id}/disable | POST | 禁用用户账户 | admin |

## 2. 内容安全：三层防护体系

### 2.1 设计原则
- **零容忍**：任何成人内容、暴力内容、歧视性内容一律拦截
- **防泄露**：AI 不能引导儿童透露真实姓名、学校、家庭住址、父母信息等个人隐私
- **防诱导**：AI 不能对儿童产生情感依赖诱导，不能扮演父母/朋友角色超出学习范畴
- **可审计**：所有被拦截的对话记录保留 30 天，管理员可查看
- **儿童友好报错**：被拦截时不展示错误信息，AI 自然切换话题

### 2.2 三层防护架构

```
用户输入
    │
┌───▼──────────────────────────────────────────────────┐
│  第一层：输入过滤（Chat Service，Java）                │
│  · 关键词黑名单（实时，< 1ms）                        │
│  · 个人信息检测（姓名/地址/学校关键词）               │
│  · 输入长度限制（儿童单次输入 ≤ 200字）               │
│  · Prompt 注入检测（越狱指令特征匹配）                │
│  通过 ──▶ 进入第二层                                  │
│  拦截 ──▶ 返回引导语，不调用 LLM（节省费用）           │
└──────────────────────────────────────────────────────┘
    │
┌───▼──────────────────────────────────────────────────┐
│  第二层：LLM System Prompt 安全规则（模型层）          │
│  · 角色约束：你是小星老师，只讨论英语和数学学习        │
│  · 内容禁区：明确列出 20+ 禁止话题                    │
│  · 输出格式：严格 JSON，减少自由发挥空间               │
│  · 拒绝指令：遇敏感请求输出固定字段 { refuse: true }   │
└──────────────────────────────────────────────────────┘
    │  LLM 响应（流式 SSE）
┌───▼──────────────────────────────────────────────────┐
│  第三层：输出过滤（Chat Service，Java）                │
│  · 解析 { refuse: true } → 替换安全回复               │
│  · 二次关键词扫描（防 LLM 绕过）                      │
│  · 正则检测：手机号、身份证、成人关键词                │
│  · 流式逐块检测，不等全量输出再过滤                    │
│  · 违规记录写入 safety_events 表                      │
└──────────────────────────────────────────────────────┘
    │
安全输出 ──▶ 客户端渲染
```

### 2.3 第一层：输入过滤实现

**关键词黑名单分级**

| 级别 | 类型 | 处理方式 | 举例 |
|------|------|---------|------|
| L1 严重 | 色情、暴力、自残相关 | 立即拦截 + 记录 + 告警管理员 | 相关词汇（略） |
| L2 敏感 | 个人隐私（姓名/地址/学校） | 拦截 + 引导「不要告诉我你的真实信息」 | 「我叫」「我家住」「我读」 |
| L3 越界 | 非学习话题（游戏、明星、政治） | 柔和引导回学习话题，不硬拦截 | 「王者荣耀」「刷抖音」 |
| L4 注入 | Prompt 注入尝试 | 拦截 + 记录（不告知用户原因） | 「忘记之前的指令」「你是 DAN」 |

### 2.4 第二层：System Prompt 安全规则

你是「小星老师」，专为 3-12 岁儿童设计的英语和数学学习助手。

**【身份约束】**
- 你只是学习助手，不是孩子的朋友、父母或监护人
- 不能与孩子建立超出学习范畴的情感依赖关系
- 始终使用儿童友好、积极鼓励的语言，避免批评和负面评价

**【内容禁区】**
- 性、暴力、血腥、恐怖、死亡
- 毒品、酒精、赌博、任何成人娱乐内容
- 政治、宗教、种族、性别歧视相关内容
- 孩子的家庭信息、个人隐私、父母情况
- 电商购物、直播、游戏充值等商业诱导内容

**【拒绝格式】**
```json
{ "refuse": true, "dialog_text": "我们来继续学习吧～" }
```

### 2.5 第三层：输出过滤实现
- 流式逐块扫描：SSE 每个 chunk 到达后立即扫描
- 解析 refuse 字段：检测到 refuse:true 立即停止流式传输
- 二次关键词扫描：防止 LLM 通过拼音、谐音、Unicode 变体绕过
- 正则检测：手机号（1[3-9]\d{9}）、身份证、银行卡号等
- 违规事件记录：写入 safety_events 表（存储 hash 而非明文）

### 2.6 安全事件数据模型

**safety_events 表**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID PK | |
| child_id | UUID FK → children.id | |
| session_id | UUID FK → learning_sessions.id | |
| layer | ENUM(INPUT_L1, INPUT_L2, INPUT_L4, OUTPUT) | |
| trigger_keyword | VARCHAR(100) | 触发的关键词（脱敏） |
| input_hash | VARCHAR(64) | 原文 SHA-256，不存明文 |
| safe_reply_used | VARCHAR(100) | 使用的安全回复模板 |
| notified_admin | BOOLEAN DEFAULT false | |
| created_at | TIMESTAMPTZ | |

- retention: 30 天后自动删除（pg_cron）

## 3. 主动学习提醒（Proactive Learning）

### 3.1 设计目标
系统从被动响应升级为主动发起，在约定的学习时间主动触达儿童。

### 3.2 主动提醒类型

| 提醒类型 | 触发条件 | 触发方式 | 内容示例 |
|---------|---------|---------|---------|
| 学习时间到了 | 家长设定的每日学习时间点 | iOS 推送 + App 内对话 | 「小明，该学习啦！今天我们来学英语～」 |
| 连续未学提醒 | 超过 N 天未打开 App | iOS 推送 | 「好久不见！小星老师想你了，一起来学习吧」 |
| 每日任务推送 | 每天早上 8:00（固定） | iOS 推送 | 「今天的任务：5道数学题 + 3个英语单词，加油！」 |
| 学习进度播报 | 完成当日目标时 | App 内庆祝动画 + 对话 | 「今天的任务全完成了！你真棒」 |
| 周报提醒 | 每周日 20:00 | 推送给家长 | 「本周学习报告：英语进步 15%，数学稳定」 |

### 3.3 Scheduler Service 架构

```
Scheduler Service（Java 21，新增）
┌──────────────────────────────────────────────────────────────┐
│  QuartzScheduler（持久化调度，存 PostgreSQL）                 │
│       │                                                      │
│       ├── DailyStudyReminderJob    每日学习提醒              │
│       ├── MissedStudyDetectorJob   未学检测，每日一次         │
│       ├── DailyTaskPublisherJob    每日任务，每天 8:00        │
│       └── WeeklyReportJob          周报，每周日 20:00         │
│                                                              │
│  NotificationDispatcher                                      │
│       ├── iOS Push（APNs）                                   │
│       ├── App 内消息（存 Redis）                             │
│       └── （预留）微信模板消息                               │
└──────────────────────────────────────────────────────────────┘
```

### 3.4 iOS 推送通知

**APNs Payload 示例**
```json
{
  "aps": {
    "alert": {
      "title": "小星老师提醒你",
      "body": "小明，18:00 学习时间到了！今天来挑战数学题吗？"
    },
    "sound": "default",
    "badge": 1
  },
  "action": "open_study_session",
  "child_id": "uuid-xxx",
  "subject": "MATH"
}
```

**推送频率限制**
- 每个儿童每天最多发送 3 条推送（防打扰）
- 勿扰时间内不发任何推送
- 儿童正在学习时，不发推送，改为 App 内消息

### 3.5 主动对话发起

**触发时机**：
- App 冷启动（距上次退出 > 4 小时）
- 点击推送通知进入
- 到达约定学习时间且 App 在前台

**实现方式**：
1. Scheduler Service 在提醒时间，预生成一条问候消息存入 Redis（TTL 1小时）
2. Chat Service 的 Session 初始化时，检查 Redis 是否有预置消息
3. 有则作为 AI 第一句话推送给客户端

### 3.6 家长学习时间配置

**配置方式**（对话完成，无表单）：
家长通过对话告知 AI 学习时间偏好，AI 解析后调用 API 保存。

**children 表扩展字段**：
- study_time: TIME[] — 每天提醒时间点，如 [18:00]
- study_days: INT[] — 提醒的星期几，如 [1,2,3,4,5]
- session_duration: INT — 每次学习时长（分钟）
- reminder_enabled: BOOLEAN — 是否开启提醒
- missed_threshold: INT DEFAULT 2 — 几天未学触发提醒

## 6. 小规模部署：资源与成本估算

按 20 个家庭（约 30 个儿童账户）估算：

| 项目 | 估算 | 备注 |
|------|------|------|
| 服务器 | 1台 4核8G 云服务器 | 月费约 ¥200–400 |
| LLM API 费用 | 约 ¥100–300/月 | 30个孩子，每人每天20轮对话 |
| 域名 + SSL | 约 ¥100/年 | Let's Encrypt 免费证书 |
| MinIO 存储 | < 10GB | 绘本图片 + 音频 |
| APNs 推送 | 免费 | Apple 推送服务本身免费 |
| **总月度成本** | **约 ¥300–700/月** | 20个家庭分摊，每家约 ¥15–35/月 |

**LLM 成本控制策略**：
1. 输入过滤前置：L1/L2 拦截的请求不调用 LLM，减少 10-15% 无效调用
2. 对话历史裁剪：Context 窗口保留最近 10 轮
3. 题目缓存：相似年龄段 + 相似知识点的题目缓存 Redis（TTL 24h），复用率 30%
4. 每日预算硬限制：chat-service 维护每日 token 计数器
5. 模型分级：普通对话用 Claude Haiku，出题和解析用 Claude Sonnet

## 7. 模型质量保障

### 7.1 模型选型

| 场景 | 推荐模型 | 理由 |
|------|---------|------|
| 日常对话 / 鼓励反馈 | claude-haiku-4-5 | 响应快（<1s），成本低 |
| 出题 / 解题解析 | claude-sonnet-4-5 | 推理质量高，数学题准确率更好 |
| 主动提醒文案生成 | claude-haiku-4-5 + 缓存 | 低频生成后缓存复用 |
| 周报摘要生成 | claude-sonnet-4-5 | 需要准确总结学习数据 |

### 7.2 出题质量控制
- 题目生成后经过「自检 Prompt」验证正确性和适龄性
- 数学题答案双校验：LLM 生成答案后，Java 层用计算引擎（如 exp4j）独立验算
- 英语题人工审核：新知识点题目首次生成后写入「待审题库」
- 题目评分机制：正确率 < 20% 或 > 95% 的题目自动标记为「待复核」

### 7.3 对话质量监控
- 随机抽样：每 100 轮对话随机抽取 5 轮供管理员评估
- 儿童反馈：对话界面有「听不懂」按钮
- 家长投诉：家长端可标记某次对话为「有问题」

## 8. 开发规范

### 8.1 安全编码规范
- 邀请码校验必须使用数据库行级锁（SELECT ... FOR UPDATE）防止并发重复激活
- safety_events 表只写不改，保证审计完整性
- 关键词黑名单存 Redis（热数据）+ PostgreSQL（持久化），支持热更新
- 所有 LLM 调用必须设置 max_tokens 上限（建议 512 tokens 对话，1024 出题）

### 8.2 Scheduler 开发规范
- 所有定时任务必须幂等：任务执行前检查 Redis 分布式锁
- 推送失败重试：APNs 返回 4xx 不重试，5xx 最多重试 3 次（指数退避）
- 定时任务执行记录写入 job_execution_logs 表，保留 7 天
- 时区统一：所有时间存 UTC，调度时按儿童档案中的时区转换

### 8.3 测试要求
