# 题目按日期分配与今日目标星星

**日期**: 2026-03-26

---

## 需求定义

### 目标

学习计划开始时，将题目预先分配到14天中的每一天，后端计算并返回今日目标星星数，前端不再自行计算。

### 核心变化

| 现状 | 目标 |
|------|------|
| 题目无归属日期，随机取 | 题目生成时分配到具体日期 |
| `todayMaxStars` 由前端从 `mockQuestions` 硬算 | 后端返回今日目标星星数 |
| 无任务时顶部卡片仍显示 0/8 | 无任务时显示休息提示 |
| `getNextQuestion` 无题时返回 null | `getNextQuestion` 返回今日总结（含是否有题、目标星星） |

---

## 数据模型变更

### Question 表

增加 `scheduled_date` 字段（DATE，可空）：
- 题目在学习计划创建时预分配到具体日期
- 取题时只取 `scheduled_date = today` 的题目
- 为 NULL 表示未分配日期（老数据或临时题）

### ApiResponse 规范（RFC 7807）

- 异常走 `ProblemDetail`（HTTP 4xx/5xx）
- 成功响应走 `ApiResponse<T>`（HTTP 200）
- 业务错误也返回 HTTP 200 + `ApiResponse.fail(code, message)`

**请求**:


## 题目分配逻辑

`confirmPlan` 时执行：
1. 从题库查询 `subject + difficulty` 匹配且 `scheduledDate = NULL` 的题目
2. 打乱顺序，均匀分配到 `durationDays` 天（从今天起）
3. 每道题设置 `scheduledDate = today + dayIndex`

---

## 实施注意

1. **Migration**: V17 需在生产环境执行，初始化所有已有题目的 `scheduled_date = NULL`
2. **向后兼容**: `scheduled_date = NULL` 的题目暂不参与取题（避免随机取到未分配的题）
3. **Real 模式**: `todayMaxStars` 由后端 summary 实时更新，前端不参与计算
4. **Mock 模式**: 前端仍从 `mockQuestions` 计算，保持开发调试能力
