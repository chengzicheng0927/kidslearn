# 题库预生成与计划匹配方案

> **目标**：将题目生成从"实时 LLM 生成"改为"预生成题库 + 激活时匹配"，大幅提升响应速度。

**最后更新**：2026-03-31

---

## 一、现状问题

| 问题 | 描述 |
|------|------|
| 实时生成慢 | LLM 生成题目需要 1-3 分钟，用户等待体验差 |
| 不稳定 | LLM 生成质量波动，可能失败或格式错误 |
| phase 分配错乱 | `assignQuestionsToPlan` 按 subject+difficulty 随机分配，完全忽略 plan.phases 中的 topic |
| 题目与阶段不匹配 | phase1 可能是乘法题，而不是计划中的加减法题 |

---

## 二、整体设计

### 2.1 设计原则

- **题库与孩子解耦**：题库按 `年级 + 科目 + topic` 组织，不绑定孩子
- **预生成优先**：后台定时 + 按需触发，提前准备好各阶段题库
- **激活时匹配**：制定计划后，激活时从题库按 topic 匹配分配，不依赖 LLM 实时生成

### 2.2 Topic 来源与扩展

**Topic 来自 `learning_stage_definitions` 表**（V5 迁移已初始化，18个 topic）：

```
英语（en，9个）: EN_VOCAB_ANIMALS → EN_VOCAB_FRUITS → ... → EN_READING_ADV
数学（ma，9个）: MA_NUMBER_10 → MA_ADD_SUB_10 → MA_ADD_SUB_20 → ... → MA_APPLICATION
```

表结构：
```sql
learning_stage_definitions (
    id          VARCHAR(50) PRIMARY KEY,  -- 即 topic_key，如 MA_ADD_SUB_100
    subject     VARCHAR(5),
    topic       VARCHAR(100),             -- 中文名，如 100以内加减法
    min_age, max_age, next_stage_keys, sort_order
)
```

**题库按 `topic_key`（= learning_stage_definitions.id）组织，不按年级**：
- 年级和年龄不是严格对应的（8岁可能是二年级也可能是三年级）
- 题库按 topic 生成，按 difficulty 区分
- 年级的作用是**过滤 topic**：哪些 topic 适合这个孩子

**后续补充新 Topic 的两种方式**：

| 方式 | 操作 | 示例 |
|------|------|------|
| 垂直扩展（同学科深化） | INSERT 新 row 到 learning_stage_definitions | 新增 `MA_TIME_CLOCK`（时分秒）|
| 水平扩展（新科目） | INSERT 新 row + subject='sc' | 新增 `SC_NATURE_BASIC`（自然科学）|

```sql
-- 补充数学新 topic（垂直扩展）
INSERT INTO learning_stage_definitions
    (id, subject, topic, min_age, max_age, next_stage_keys, sort_order)
VALUES
    ('MA_TIME_CLOCK', 'ma', '认识钟表', 6, 8, ARRAY['MA_ADD_SUB_20'], 19);

-- 题库生成器会在下次 cron 自动发现它 → 检查水量 → 触发生成
```

**补充后自动生效**：
```
learning_stage_definitions 插入新 row
    ↓
定时任务遍历所有 learning_stage_definitions.id 作为 topic_key
    ↓
查 question_bank 统计该 topic 现有题数
    ↓
发现 < min-waterline（50）→ 自动触发生成任务
```

**无需修改代码**，定时任务直接读取 `learning_stage_definitions` 动态发现所有 topic。

### 2.3 题库表结构（修改版）

```
题库（question_bank）
├── subject     # 科目（en / ma）
├── topic_key   # 主题Key（MA_ADD_SUB_100，来自 learning_stage_definitions）
├── difficulty  # 难度（easy / medium / hard）
└── questions[] # 预生成的题目列表
```

**每道题目结构**：

### 2.3 数据流

```
[定时任务 / API 触发]
        ↓
[题库生成器] ——调用 LLM 生成题目
        ↓
[question_bank 表]（按 grade+subject+topic 存储）
        ↓
[用户制定计划]
        ↓
[用户激活计划时]
        ↓
[按 plan.phases[].topic 匹配题库] ——纯查库，速度极快
        ↓
[建立 plan_questions 关联]
```

## 三、数据库设计

### 3.1 新增表：question_bank

```sql
CREATE TABLE question_bank (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    -- 题目归属
    grade               VARCHAR(20) NOT NULL,    -- 年级：一年级、二年级...
    subject             VARCHAR(5) NOT NULL CHECK (subject IN ('en', 'ma')),
    topic               VARCHAR(100) NOT NULL,    -- 主题：100以内加减法
    topic_key           VARCHAR(50) NOT NULL,    -- 主题Key：MA_ADD_SUB_100

    -- 题目内容
    difficulty          VARCHAR(10) NOT NULL CHECK (difficulty IN ('easy', 'medium', 'hard')),
    label               VARCHAR(255) NOT NULL,
    question            TEXT NOT NULL,
    options             JSONB NOT NULL,           -- [{"id": "a", "text": "82"}, ...]
    correct_answer_id   VARCHAR(10) NOT NULL,
    explanation          TEXT NOT NULL,
    explanation_steps    TEXT[] NOT NULL,
    encouragement       TEXT NOT NULL,

    -- 元数据
    estimated_minutes   INT NOT NULL DEFAULT 3,
    reward              JSONB NOT NULL DEFAULT '{"stars": 8, "xp": 18}',

    -- 状态
    status              VARCHAR(20) NOT NULL DEFAULT 'approved'
                            CHECK (status IN ('pending', 'approved', 'generating', 'failed')),

    -- 生成记录
    generation_model    VARCHAR(50),
    generation_prompt   TEXT,
    generated_at        TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    UNIQUE(subject, topic_key, difficulty, question)  -- 防止重复
);

CREATE INDEX idx_bank_grade_subject ON question_bank(grade, subject);
CREATE INDEX idx_bank_topic ON question_bank(subject, topic_key);
CREATE INDEX idx_bank_status ON question_bank(status) WHERE status = 'generating';
```

### 3.2 新增表：bank_generation_task（生成任务记录）

```sql
CREATE TABLE bank_generation_task (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    -- 生成范围
    grade               VARCHAR(20) NOT NULL,
    subject             VARCHAR(5) NOT NULL,
    topic_key           VARCHAR(50) NOT NULL,

    -- 生成参数
    difficulty          VARCHAR(10),
    target_count        INT NOT NULL DEFAULT 20,  -- 目标数量
    questions_generated INT NOT NULL DEFAULT 0,   -- 已生成数量

    -- 状态
    status              VARCHAR(20) NOT NULL DEFAULT 'pending'
                            CHECK (status IN ('pending', 'generating', 'completed', 'failed')),

    error_message      TEXT,

    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    completed_at        TIMESTAMPTZ
);
```

### 3.3 修改 plan_questions 关联

现有 `plan_questions` 表不变。激活计划时，从 `question_bank` 匹配题目，建立关联。

## 四、题库生成器设计

### 4.1 核心接口

```java
public interface QuestionBankService {

    /**
     * 触发题库生成（按 topicKey，按 learning_stage_definitions 确定年级范围）
     * @param topicKey    主题Key（如"MA_ADD_SUB_100"，来自 learning_stage_definitions.id）
     * @param difficulty  难度（easy / medium / hard）
     * @param count       生成数量
     */
    void triggerGeneration(String topicKey, String difficulty, int count);

    /**
     * 批量触发题库生成（用于定时任务，动态读取 learning_stage_definitions）
     */
    void triggerBatchGeneration();

    /**
     * 从题库匹配题目分配到计划
     * @param planId  计划ID
     * @param phases  计划阶段（含 topic）
     */
    void assignQuestionsFromBank(UUID planId, List<Map<String, Object>> phases);
}
```

### 4.2 定时任务配置（补充缺口，不是重复生成）

```yaml
# 每天凌晨 3:00 检查题库缺口
bank-generation:
  cron: "0 0 3 * * ?"
  min-waterline: 50
  max-waterline: 100
  default-batch-count: 50
```

**定时任务逻辑**：
```
遍历 learning_stage_definitions 所有 topic（动态发现，无需写死）
    ↓
查询 question_bank 统计该 topic+difficulty 现有题数
    ↓
题数 >= min-waterline（50道）？
    → 充足，不生成
    ↓ 不足
题数 < min-waterline → 创建 bank_generation_task（原子操作，unique index 防并发）
    ↓
@Async runAsyncGeneration() → LLM 生成 → 入库 → task.status = completed
```

**题库规模估算**（合理）：
- 6个年级 × 2个科目 × 平均10个topic × 100道（max-waterline）= **约12000道题**
- 每天补充缺口，题库稳定在 10000-12000 条，不会无限膨胀

### 4.3 生成流程（异步 + 状态驱动）

```
定时任务触发（不等待完成）
    ↓
查询 question_bank，按 grade+subject+topic 检查现有数量
    ↓
数量不足 → 为每个 topic 创建 bank_generation_task（status=generating）
    ↓
异步调用 LLM 生成 N 道题目（@Async，不阻塞 cron 返回）
    ↓
LLM 生成完成 → 批量插入 question_bank → 更新 task.status = completed
    ↓
定时任务下次运行时，轮询检查 pending/generating 任务 → 继续执行或重试
```

**关键点**：
- LLM 生成是**异步的**，cron 触发后立即返回，不阻塞
- 状态机驱动：`pending` → `generating` → `completed/failed`
- 下次 cron 运行时检查 `status != completed` 的任务，继续执行

### 4.4 如何避免同一学生重复做题

```
assignQuestionsFromBank 查询时，按【学生维度】排除：

SELECT * FROM question_bank
WHERE grade = :grade
  AND subject = :subject
  AND topic_key = :topicKey
  AND difficulty = :difficulty
  AND status = 'approved'
  AND id NOT IN (
      -- 排除这个学生在所有计划中已做过的题目
      SELECT pq.question_id FROM plan_questions pq
      JOIN learning_plans lp ON lp.id = pq.plan_id
      WHERE lp.child_id = :childId
  )
ORDER BY RANDOM()
LIMIT :neededCount
```

效果：
- ✅ 不同学生可以做相同题目（题库共享，省资源）
- ✅ 同一学生不做重复题目（跨所有计划去重）

## 五、计划激活时匹配

### 5.1 assignQuestionsFromBank 逻辑（两种模式）

```
confirmPlan 被调用
    ↓
获取孩子的年级（child.grade）和 childId
    ↓
检查 plan 是否有已分配的 questions？
    ↓ 是（LlmService 已调用 generate_questions 保存了题目）
    → 跳过，直接完成激活
    ↓ 否（题库模式）
    ↓
按 plan.phases 遍历每个阶段
    ↓
  查询 question_bank（按学生维度排除已做过的题目）：
    WHERE topic_key = phase.topicKey
      AND difficulty = phase.difficulty
      AND grade = child.grade（优先）
      AND status = 'approved'
      AND id NOT IN (SELECT question_id FROM plan_questions WHERE child_id = :childId)
    LIMIT questionsPerDay * 2
    ↓
  打乱 + 取需要数量
    ↓
  写入 questions 表（复制题目内容） + plan_questions 关联（phaseIndex、purpose='practice'）
    ↓
  下一阶段...
    ↓
  题目不足？
    → 记录警告日志 BANK_INSUFFICIENT
    → 继续，不阻塞激活流程
    ↓
  assignQuestionsFromBank 异常？
    → fallback 到原有的 assignQuestionsToPlan（按 subject+difficulty 随机分配）
```

### 5.2 两种模式的判定

| 判定条件 | 模式 | 说明 |
|---------|------|------|
| `plan_questions` 有数据 | LLM 实时模式 | `generate_questions` tool 已预先分配 |
| `plan_questions` 无数据 | 题库模式 | 从 `question_bank` 匹配分配 |
| 题库不足或查询异常 | Fallback | 回到原有的 `assignQuestionsToPlan` |

## 九、风险与备选

| 风险 | 缓解方案 |
|------|---------|
| 题库数量不足 | 降级到实时 LLM 生成，边缘话题优先补充题库 |
| LLM 生成重复题目 | question_bank 加唯一索引去重，重复时跳过 |
| 定时任务生成量太大 | 控制并发数，分批生成 |
| topic 覆盖不全 | 先支持人教版核心 topic，逐步扩展 |
| 定时任务每天重复生成大量题目 | 改为检查题库水位，不足才生成；每天补充到 min-waterline（50道）后停止 |
| 题库无限膨胀 | 设置 max-waterline（100道）上限；超过不生成；实际约12000道题封顶 |
| 同一学生重复做相同题目 | 按 childId 维度排除：NOT IN (SELECT question_id FROM plan_questions JOIN learning_plans WHERE child_id = :childId) |
